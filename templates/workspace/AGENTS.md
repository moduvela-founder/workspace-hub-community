# 工作空间规则模板

这是供使用者合并的通用模板，不是原作者的工作空间文件。先把 `<实际Hub目录>` 换成自己的 Hub 绝对目录；保留已有规则，只合并适用条目，不直接覆盖文件。

- 本工作空间包含多个独立项目。先确定目标产品、所属仓库和实际工作区，再读其适用 AGENTS 与直接相关文档；项目自身需求、参数、门禁和验收仍然有效。
- 项目初始化、首次整理、状态更新或共享能力查询时，按需读取 `<实际Hub目录>/docs/hub/README.md`。可用 `node <实际Hub目录>/scripts/hub.mjs rules --summary --json` 检查规范变化；已知入口直接读取，首次或上下文缺正文时仍读，只有正文未变且仍保留时复用。
- 新项目、独立功能或主线实质变化时，读取 `<实际Hub目录>/docs/hub/delivery-workflow.md`，在已有状态或计划中明确目标、当前模式、验收条件和本轮终点。新探索优先最小 DEMO，已有生产承诺继续有效；非阻塞改进不扩大当前范围。
- 本轮涉及界面设计、实现、文案或布局审查时，读取 `<实际Hub目录>/docs/hub/ui-delivery.md`。研发说明留文档，保留必要操作、真实状态与反馈；按项目约定的视口、滚动范围和主线操作验收。非 UI 工作不因此加载界面规范。
- 首次生成构建/测试输出、选择存储位置或阶段收尾前，读取 `<实际Hub目录>/docs/hub/storage-and-outputs.md`。先核对输出归属和既有布局；真实路径、卷身份和工具参数留在自己的配置或拥有文档，不把外置盘当所有项目的统一 OUT 设置。
- 实施或验证改变事实后，按 `<实际Hub目录>/docs/hub/document-contract.md` 更新已有 STATUS 和人工步骤文档；分析保持只读，不重复建立事实来源。未勾选事项不自动等于当前任务阻塞，仍遵守实际适用的门禁。
- 共享规则引用和目录登记只是导航，不授权安装工具、发送消息、发布、清理资料或操作设备；这些动作按当前有效授权和目标项目边界处理。

模板放在父目录，不保证 Codex 会跨越各独立 Git 项目根自动加载。每个独立项目仍应保留自己的短入口，或由使用者选择合并 `examples/codex/GLOBAL-AGENTS-SNIPPET.md` 的全局导航建议。子 agent 使用约定也在该可选建议中，不必复制整份全局规则。
