# 开发文档契约

## 稳定入口

新建纳入管理的产品/独立资产主目录时使用四文件约定：

| 文件 | 职责 | 更新触发 |
| --- | --- | --- |
| README.md | 定位、使用方式、目录和关联资源入口 | 长期定位或入口变化 |
| AGENTS.md | 行为约束、必读触发、验收与审批要求 | 稳定规则变化 |
| STATUS.md | 当前目标、阶段、确认结果、阻塞和下一步 | 实施、验证或已批准目标变化 |
| MANUAL_STEPS.md | 人工、现场、审批或外部条件事项 | 新增、变化或有完成依据 |

这是主目录约定，不要求在每个共享仓库、worktree 或镜像复制产品状态。已有进度/人工步骤文档符合职责时，在目录中映射 `statusFile` / `manualStepsFile`；不创建第二份权威来源。特殊产品文档门不受模板取代。

映射还须满足读取格式：`statusFile` 使用本契约的受控 YAML 前言，`manualStepsFile` 的可计数事项使用 Markdown 复选项。纯文字旧文档可以继续作为来源，但不能仅声明映射就称工作台已解析状态或待办；在授权整理中给原文档补最小元数据/事项结构，保留正文与既有门禁，不另建重复文件。没有复选项时不能将计划段落推断为零项已确认待办。

AGENTS 采用[共享规则短入口](project-rules.md)，保留项目自己的触发、例外和验收门，不复制中央规范全文或个人环境表。新模板由实际 Hub 目录生成链接；已有文件只在授权整理中合并必要入口。规范更新靠按需读取，不承诺自动同步已有项目文件。首次构建/测试输出、路径变化及阶段收尾另按[存储与输出约定](storage-and-outputs.md)核对归属、配置和保全条件。

## STATUS.md

以 YAML 前言提供可读字段，正文保留简短的证据、未知、阻塞和下一步：

```yaml
schemaVersion: 1
id: demo-project
title: 示例项目（虚构）
kind: product
goal: "当前已确认目标；未确认时明确待澄清"
stage: intention
activity: unknown
readiness: unknown
startedAt: null
confirmedAt: null
```

初始化默认推进状态和可用性为 unknown；只有证据明确时才填写其他值。枚举见[资产模型](asset-model.md)。`confirmedAt` 使用 ISO 日期，只有复核目标/状态依据后更新；初始化时间不能证明状态已确认。目标变更写出批准来源与原因，并链接原需求/决定，不把聊天里的提议静默变成要求。

`startedAt` 使用 ISO 日期或 `null`，记录真实起始日期。初始化创建不存在的新目录时为当天；已有目录补缺失文档默认 `null`，只有明确依据才补齐。已有日期保留，首次整理的旧项目若无明确依据则为 `null`。登记、Git 提交和文件修改时间不能代替起始日期；日常状态更新不改它。

分清“已确认”“本次完成与证据”“未知/限制”“阻塞”“下一步”。硬件、结构分别表达设计、仿真、打样、装配和实测；无需填写无法度量的百分比。记录测试范围与结果链接，不复制原始日志。发布交接与发布成功不同，按原流程门描述。

### 当前执行约定

有开发任务时，依照[DEMO 与产品化推进约定](delivery-workflow.md)，在 STATUS 正文或已有权威任务计划中维护以下短约定；STATUS 可链接后者，不复制第二份。本节不新增 YAML 字段，不改变 `stage` 枚举，也不要求没有开发任务的资料/工具填写。

```text
对象与目标：当前功能/里程碑及本轮唯一主线
当前模式：DEMO 验证 / 产品化；未确定则标推荐或待确认
本轮终点：DEMO 验收 / 功能交付（列出包含的产品化事项）
验收条件：操作条件、可观察结果和必要证据
本轮 gate：适用的来源条目、约束的动作/阶段与通过条件；未明确时标待澄清
最小实现与边界：选定路线与复用/复现入口；有可用参考时注明关键组合、必要适配及选择依据；允许简化与必须遵守的项目约束
暂缓事项：不阻塞当前验收的问题及其已有待办入口
```

小任务可合并成一两句话。已有约定未变时复用；模式、目标或终点变化时记录依据。DEMO 通过不自动把整个产品标成 `delivered` / `verified`；结果仍按实际验证范围表达。多功能约定放已有计划，STATUS 只汇总当前重点。

涉及 UI 时，验收条件补充内容区视口、页面缩放、核心操作与滚动范围，链接已有界面/验证说明即可；默认参数见[界面验收](ui-delivery.md)。这些仍是正文约定，不新增 YAML 状态字段，不为每轮界面调整另建管理文档。

## MANUAL_STEPS.md

使用简短复选项，每项包含需要谁/什么条件、动作、完成标准和证据入口；没有已知事项时明确“暂无已确认人工步骤，现场验证范围待确认”。缺证据的事项保持未完成。登记事项本身不构成执行、审批或设备操作授权；实际动作按已有用户授权与目标项目边界处理。

未勾选只表示该人工事项尚未完成，不自动表示阻塞当前任务。当前执行约定应引用真正适用于本轮的 gate（原条目名称、已有标识或章节链接），写清约束哪个动作/阶段以及通过条件；后续产品化或发布事项不因尚未勾选就提前成为 DEMO 前置条件。既有强制门禁仍有效，遗漏引用不能作为绕过理由。Hub 的待办计数保留全部未勾选事项，不代替 gate 判断或自动修改阻塞状态。

## 文档增长边界

新增文档前检查已有事实来源。当前进度更新 STATUS；设计/协议/参数更新其拥有文档；确需独立的设计、ADR、测试证据从 README 或相关状态链接。临时计划、扫描日志和任务收尾不都变成一份新 Markdown。当前工件、证据及保留入口沿用拥有文档；原始证据未经授权保持原位，获授权的迁移/退役遵循存储约定，不自动删除、移动、改名或归档历史文件。

只读分析/审查不改状态。实施收尾仅更新被本次工作改变的事实，不为普通对话改日期或清空旧人工步骤。多个会话共用目录时由一个写入者维护状态，总览只读汇总。

向其他会话提供入口时，优先用[资产短引用](asset-model.md#查询与短引用)和来源链接；不复制历史长摘要到 AGENTS 或新的收尾文档。解析引用后仍需读取本次相关的项目约束与最新依据。

## 手动结项整理

用户需要归纳已结束会话的问题、根因、最终决策和证据时，显式调用 `$session-closeout`，见[技能入口](../../skills/session-closeout/SKILL.md)。按上面的拥有文档职责更新已有内容；一次会话结束不代表整个产品交付。该流程不在任务完成、提交或定时检查时自动触发，也不自动压缩、归档或删除会话。
