# 存储与输出约定

在本轮首次生成构建/测试输出、调整存储位置、阶段收尾或退役临时目录/worktree 前读取；选择大文件位置、Docker 数据、发布包、游戏库或实施迁移也使用本约定。这里维护可复用原则；真实卷名、UUID、挂载路径和迁移结果由目标机器的环境规程维护，不复制到所有项目。

## 首次生成输出前

先确定输出归属，再创建目录或运行产生文件的命令：

1. 确认产品/资产入口、所属仓库、实际 checkout/worktree 或临时源码副本，以及负责本轮输出与收尾的 owner；无 Git 资产使用其已有主目录确定归属。产品主目录、Git 仓库和实际工作区可能不同；不能只凭当前工作空间目录或产品名称决定归属。
2. 读取目标项目的适用 AGENTS、README、构建/测试配置及已有存放约定，确认当前权威入口、正在写入的任务和工具支持的输出参数。共享仓库的独立工作区分别隔离输出；共用缓存仅在工具支持且项目明确约定时使用。
3. 优先沿用已有工具链布局和已批准的外盘配置；没有既有约定的新输出，使用下面的仓库内默认位置。配置必要的忽略规则后再生成输出，不把目录创建当成搬迁、清理或发布授权。

同一任务中归属、工作区和配置未变化时可复用已核对的约定，不逐文件重复确认；切换工作区、输出用途或位置时重新核对。日常路径选择可在现有授权内完成；只有缺失选择会改变范围、外部影响或安全时才询问用户。

| 内容 | 默认位置与保留要求 |
| --- | --- |
| 可重建构建中间物、缓存、临时运行环境 | 所属仓库实际工作区的 `.local/build/`；确认可重建且无活动写入后才可按授权清理 |
| 原始测试/验收证据、录音、诊断日志、抓包、本地报告 | `.local/evidence/`；需要长期作为依据时保留原始资料、来源和校验值，并在拥有仓库的跟踪文档中保留摘要入口 |
| 待审候选包、BIN/ELF、安装包及工件本地副本 | `.local/artifacts/`；区分候选、本地留存与正式发布版本，保留必要构建配置和校验值 |
| 源码、测试 fixture、新增文件、参数、协议、验收摘要、BOM/manifest 和工件哈希 | 所属仓库的跟踪目录；临时未提交源码在收尾前单独保全，不能仅依赖忽略目录或聊天 |
| 已冻结的正式工件 | 沿用项目既有版本化 Release/TOS/归档入口；拥有仓库维护清单、发布依据和当前权威入口，不复制第二套正式发布源 |
| 密钥、授权配置、含秘密的恢复备份 | 沿用既有秘密存储和私有保留位置；不因加入 gitignore 而放入普通源码、证据索引或未批准的归档 |
| 其他设备恢复资料、源码快照与备份 | 按拥有项目的恢复用途和保留决定单独存放；确认保全范围及可读取性，不与缓存一起整目录删除 |

允许在上述输出目录内部按任务、平台、配置和版本建立子目录。默认不在多项目工作空间根部每轮另建共享 `build-*`、`release-*`、`evidence-*` 目录。跨仓联合验收等确需产品级目录时，由产品拥有文档明确责任、成员仓库、实际工作区、入口及保留约定；不把普通仓库输出全部汇入共享根。

各独立仓库自行维护并检查忽略规则；父仓的 `.gitignore` 不能代替子仓的规则，已跟踪文件也不会因新增忽略规则自动退出 Git。`.local` 可能同时保存服务配置、布局、证据和未提交文件，不能宣称整个目录可删。当前 `init` 只补四个标准文档，不自动建立输出目录或修改 `.gitignore`。

实际采用的路径、例外、当前工件及证据入口写入项目已有 README、构建配置或验收文档，状态变化时从 STATUS 引用；不为每轮任务新增一份权威目录说明或复制中央规范。新项目模板保留短读取触发；旧项目仅在获授权的整理中合并必要入口，不批量覆盖现有 AGENTS。

本约定是工作约束，Hub 当前没有自动阻止目录创建、自动迁移/清理或强制同步旧项目的功能。规则调整本身不授权处理任何已有资料。

## 分配原则

| 内容 | 默认选择 |
| --- | --- |
| 日常源码、项目文档、工作台、开发工具及配置 | 常在线的本机盘，保持原项目入口 |
| 大型镜像、素材、参考资料、归档与游戏文件 | 可按容量需要放在外接盘；重要原始资料仍需要独立备份 |
| 小型固件、普通网页的编译输出 | 沿用项目现有配置，不因新增外盘强制迁移 |
| 大型或多平台构建输出 | 可配置到外盘，按项目/平台/配置隔离 |
| 发布制品本地留存 | 按项目/版本保存；版本清单、校验值和发布依据留在拥有项目 |

实际路径由项目支持的构建参数、应用设置或本机未跟踪配置提供；共享仓库避免写死用户名和个人卷路径。项目 AGENTS 只记录读取触发与必要约束，具体命令和输出策略放在 README、构建配置或已有参数文档。外置输出不是所有项目都支持的全局 OUT 开关；尊重项目工具链和批准的构建布局。

文件系统应满足目标工具的权限、符号链接和大小写要求。Mac 专用 SSD 可采用不区分大小写的 APFS；加密是独立选择，未设置密码不能宣称已加密。不要为了跨平台兼容而改变已经批准的 Mac 专用方案。

## 可用性与迁移

依赖外盘的操作先核对实际挂载、目标卷身份与可写性，不能只检查目录存在。缺盘或身份不符时停止依赖操作并报告；不创建伪挂载目录，不静默写回内置盘。索引仍可展示离线入口，但不能把历史路径当成当前可读文件。

迁移时暂停相关写入，保留隐藏文件、权限、符号链接及稀疏文件语义；验证完成前保留旧副本。沿用目录结构可减少引用变更，但仍核对应用配置、卷身份和 Git worktree 关联。移动项目/资料后只登记已批准的具体读取根，不放宽索引到整个外盘；构建输出、游戏与备份不因此成为知识库扫描范围。

历史 BOM、manifest、验收记录中的绝对路径和哈希保留其原始内容。获授权的迁移新增原路径、目标入口、来源版本及校验结果的映射收据，由拥有文档更新当前入口；不能为了统一目录改写已冻结记录。兼容链接仅在明确采用时保留，不能猜测缺失路径应重新创建。新清单在工具支持时采用相对归档路径或稳定工件标识，并保留版本和哈希以便解析。

## 阶段收口与临时工作区退役

先确定本阶段和拟退役目标的 owner、精确路径及已有保留/清理授权，暂停相关写入。当前阶段完成不要求所有其他工作都合并，也不授权接管其他会话的活动目录。

1. 核对来源提交、分支和实际工作区；同时检查已跟踪改动、未跟踪文件，以及拟退役目录内被忽略的源码、fixture 和补丁。提交已合并或 `git status` 没有显示改动，都不能替代这次核对。
2. 将应纳入开发线的改动按本项目验收门收口；未完成或含独有提交的分支保留。需要保留的临时/故障测试另存完整源码和必要基线、依赖及配置；patch 不能替代新增文件，也不把实验源码混入正式工件。源码快照、原始证据和构建缓存分别判断。
3. 找出必要最终工件、BOM/manifest、配置、日志、原始验收证据与恢复资料。用已有拥有文档明确当前权威版本、工件和证据入口，保留来源提交及必要校验值；不要按日期最新的目录推断权威版本。
4. 需要迁移或归档时，先按对应类别保全并校验原始资料与来源，核对路径引用和访问方式。完整恢复包、证据子集和可重新下载工件分别标明；保全副本不等于恢复演练或独立备份。未知内容、唯一证据及唯一恢复资料保留，不能将整个混合目录当缓存清理。
5. 完成核对后，才在已有授权范围内清理明确可重建缓存或已保全的重复副本，退役确已结束的临时目录。Git worktree 使用 Git 或管理工具移除；移除前确认活动工作已结束，应保留的未提交/未跟踪源码及 ignored 内容已完整保全，独有提交已有可恢复的分支、标签或归档入口，需继续使用的分支保留。不直接删目录或用 prune 掩盖丢失；主 checkout、临时源码副本和外盘工作区分别处理。

阶段摘要更新已有 STATUS/验收入口，必要外部条件记入映射的人工步骤文档；详细本机清理清单、路径映射和校验收据保存在既有私有记录位置，不进入 AGENTS 或默认内容索引。确认保全完成、迁移完成、提交/推送、正式发布和实机验收分别记录，不互相代替。

目录统计与实际释放空间分别核对。父子目录、APFS 克隆共享块和活动写入会影响数值；不把目录大小相加或移入废纸篓的字节数当作已经释放的空间。

## Docker 与发布边界

Docker Desktop 的 Linux 镜像、容器和数据卷由其磁盘映像管理；迁移使用应用支持的 Disk image location 设置，不直接搬动运行中的映像。主机 bind mount 目录另外核对，数据迁移不自动删除 unused 对象或重设磁盘上限。参见 [Docker 官方迁移说明](https://docs.docker.com/desktop/troubleshoot-and-support/faqs/macfaqs/)。

TOS、GitHub/GitLab Release、DEB/APT 的云端发布与本地制品留存分开。更换本地存储不修改既有云端版本、发布地址或审批门；原发布脚本、manifest/BOM、版本与校验依据仍由产品维护。迁移完成、构建通过、发布交接与发布成功分别记录。
