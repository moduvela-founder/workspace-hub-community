# 项目采用的共享规则

供纳入工作台的产品、工具和其他独立资产引用。项目自身的指令、需求、审批和验收仍然有效；本文件不把 Workspace Hub 的开发命令施加给其他仓库。

## 分层与接入

| 层级 | 保存什么 |
| --- | --- |
| 全局 AGENTS | 跨项目的工作原则和按需入口 |
| 本规范目录 | 可复用的文档、资产、存储和接入约定 |
| 个人环境规程 | 本机卷身份、路径、账号、主机和保留决定；不放入可对外复用的项目规则 |
| 项目 AGENTS 与拥有文档 | 本项目约束、读取触发、验收门，以及实际采用的构建/发布配置和例外 |

新项目使用四文件模板，在 AGENTS 中保留共享规则的短入口。已有项目在首次获授权的整理或相关规则调整中合并入口，保留原约束和文档映射；不批量替换旧 AGENTS，也不为共享仓库或 worktree 复制产品状态。

**共享规则不自动复制到每个项目。** 中央约定更新后，项目按需读取；只有本项目的配置、接口或例外发生变化时才改其拥有文档。当前 CLI `init` 仅补缺失文件，不升级已有 AGENTS。模板中的 Hub 入口由实际安装目录生成；换机或移动 Hub 后，只修正引用入口，不复制规范正文。

## 按任务读取

| 任务 | 读取 |
| --- | --- |
| 初始化文档、实施后状态变化、整理重复文档 | [文档契约](document-contract.md) |
| 启动项目/独立新功能、改变本轮目标或交付模式、重整主线 | [DEMO 与产品化推进约定](delivery-workflow.md)；当前约定未变时复用，不每轮重做 |
| 设计、实现或审查界面、布局、文案及视口适配 | [界面信息与视口验收](ui-delivery.md)；参数与画面证据归目标项目 |
| 用户明确要求手动整理结项会话 | [session-closeout 技能](../../skills/session-closeout/SKILL.md)；仅显式调用，不作为普通收尾必做项 |
| 登记身份、仓库/能力关系、短引用 | [资产模型](asset-model.md) |
| 旧项目首次梳理、批量登记或副本冲突 | [整理流程](onboarding.md) |
| 新增资料包、角色成员或正文检索 | [资料包契约](knowledge-collections.md) |
| 首次生成构建/测试输出、存储分配、迁移或阶段收尾（含临时目录/worktree 退役） | [存储与输出约定](storage-and-outputs.md)；涉及机器路径、卷或私有保留决定时再读实际环境规程 |

首次相关任务、上下文缺失或开始下一项管理文档写入前，在 Hub 根运行 `node scripts/hub.mjs rules --summary --json`，有本会话指纹时加 `--since HASH`。首次或缺少正文时仍读相关规范；变化后用 `rules --json` 对比已保留的逐文件指纹，没有旧清单则重读当前任务相关规范。正文未变且仍在上下文中才可复用。已知入口可直达，不递归读取导航与关联文档；普通问答不触发全量读取。

Hub 指纹覆盖其 AGENTS、共享规范、模板及登记技能；不包含个人全局规则或机器规程，也不证明项目状态、设备在线或来源最新。AGENTS 的自动注入由 Codex 客户端控制，本工具不刷新整个会话的指令链。

## 开发推进

新探索与新功能优先形成最小可验证闭环，再按明确交付需要产品化；已上线修复与生产维护保留既有承诺。开始时分别明确当前模式与本轮终点，写入已有状态/计划；模式不替代资产类型或 `stage`。DEMO 按约定能力和结果选择最小路线；有匹配可用的成功参考时优先复现关键完整组合，遇到问题再判断修复、复用或替换，不默认锁定旧实现。非阻塞问题记录后继续主线，达到本轮完成标准后收口；已包含的后续交付工作在原授权内继续，不逐步重复询问。具体约定、风险取舍和可复制提示词维护在[推进流程](delivery-workflow.md)，本文件不复制其完整内容。

## 发布渠道

发布前按项目拥有文档确认受众、版本/edition、交付位置、用户下载入口及保留策略；源码仓库与安装包分发分别管理，不因使用 GitHub/GitLab 托管源码而自动创建对应 Release。内部共享目录、内网下载站、TOS 和包仓库均按已批准的项目渠道执行，具体公司地址和目录不复制到本共享规范。

交付保留来源提交、版本、平台、已有工件校验与发布说明。GitLab Release 发布后核对上传结果、Release/tag 关联，以及附件文件名、版本/平台、链接和大小等可用文件信息；SMB/内网分发以上传成功及目标目录文件名、大小等信息核对作为发布验收，保留内网网站供用户下载。两类渠道均不重新下载工件，也不要求远端哈希回验；文件信息核对与文件字节/哈希核对分别记录。TOS 及其他渠道继续按项目已有约定验收。

复制完成、网页可访问、发布成功与实机验收分别记录；分发旧版本的退役只作用于已明确的分发范围，不自动删除源码历史、BOM、原始证据、恢复资料或本机输出。涉及 Git/API 操作时再按当前环境的 Git 服务规程执行。

## 更新与交接

- 实施、验证或已批准目标变化后，只维护本次改变的事实；只读分析不改状态或确认日期。稳定参数和设计仍归拥有文档，不塞进 AGENTS。
- 新人工或外部条件记入映射的人工步骤文档；完成需要依据。记录本身不授予执行、审批、发布或硬件操作权限，已有授权按目标项目约束执行。
- 给新会话提供 `workspace-hub:资产ID` 或带 `#成员ID` 的短引用，附 Hub 位置和名称；解析后读相关项目指令和最新来源，不携带历史长摘要或整包角色正文。
- 本机路径、存储清理授权和历史验证不能当成其他机器/项目的事实。缺少依据时保留未知，不以扫描、构建或登记代替产品验证。
