# 界面信息与视口验收

设计、实现或审查网页、WebView、桌面和移动界面时按需读取。适用于 DEMO 与产品化；当前使用者、主任务和已批准界面要求优先。本页维护共用原则和默认验收参数，项目的实际布局、支持范围和验收证据留在已有设计/验证文档。

## 界面承载什么信息

默认呈现业务内容、必要操作、真实状态与简短反馈。研发说明、实现细节、开发计划、测试结论和长篇操作说明进入已有文档，不默认给每个模块添加介绍段、提示卡、架构宣传或大标题。优先用布局、控件名称和状态表达操作关系，不用解释文字弥补混乱的交互。

- 必要字段名称、单位、输入校验、错误及恢复动作、关键操作后果和确认保留在相关位置；无障碍名称和键盘焦点不能因精简视觉而消失。
- 状态变化优先替换局部状态，不反复新增提示条挤动主体；只在用户需要采取行动或了解结果时反馈。演示、未连接和真实执行状态应清楚区分，不能为整洁伪造成功。
- 不把删掉的说明全部改为 tooltip，也不默认另建日志页、调试台或帮助系统。确有诊断任务时，按其使用者需要提供信息；技术数据本身是业务内容时不一律隐藏。
- 控制台围绕操作组织；长列表、资料阅读页和营销页按各自目的布局。DEMO 可以功能少，仍保持清晰的用户界面；产品化也不意味着追加说明段或弹窗。

## 先约定页面与滚动范围

新页面或明显布局变更时，在已有执行约定/设计说明中记录：使用者、页面主任务、首屏必须出现的内容与操作、目标视口、缩放、滚动范围及必要状态。已有约定未变时复用，小修改不用重复填表。

控制台的“一屏”指约定核心内容、主操作、关键状态在正常窗口下完整可见；不要求把所有历史记录塞入一屏。列表、历史和二维内容可以使用明确的滚动区域，但不能把本应首屏可用的主操作藏入该区域。资料/长列表页允许页面纵向滚动，不能套用控制台的无纵滚判定。

## 默认网页视口参数

下面是本工作空间的设计验收默认值，不是 Mac 硬件规格，也不保证覆盖每种显示设置。已有项目有明确支持范围时沿用；新项目没有另行约定时，桌面控制台采用前两档。小窗口按实际使用范围检查退化；面向窄屏的网页补测最后一档，不把它当原生桌面应用的强制尺寸。

| 内容区视口（CSS px） | 用途 | 验收要求 |
| --- | --- | --- |
| **1440 × 800** | 常规桌面 | 控制台核心内容、主操作与状态完整一屏；约定数据区可内部滚动 |
| **1280 × 700** | 默认最小桌面一屏目标 | 同上，不能依赖浏览器全屏或缩小页面才能操作 |
| **1024 × 600** | 小窗口退化 | 可重排、单列或纵向滚动；功能可达，不能裁掉内容或产生无意义的页面横滚 |
| **390 × 844** | 窄屏布局检查 | 允许纵向滚动；页面无横向溢出，控件、弹窗和末尾内容可达 |

经常使用较矮普通窗口的项目，可额外测 **1280 × 640** 压力档，或将其明确约定为更低的一屏目标；低于本项目一屏下限时采用受控退化，不能直接裁切。视口档位由项目记录，不默默把未经测试的更低尺寸写成已支持。

统一按 **100% 浏览器页面缩放** 验收桌面一屏，使用正常产品字号与控件尺寸。尺寸指 `window.innerWidth × innerHeight`，同时记录根元素 `clientWidth × clientHeight`；不使用屏幕物理分辨率、截图像素或浏览器外框尺寸代替。macOS 显示设置、窗口、工具栏和侧栏影响可用内容区，不能统一按“屏幕尺寸减固定高度”推算；DPR 描述 CSS 像素与显示像素的比例，不代表内容区尺寸。DPR、浏览器及系统显示设置已知时一并记录，未知如实说明。

浏览器工具设置尺寸后须读回实际视口，不把请求设置的数值当成测量值。内嵌预览还应记录其可见裁切范围，不能只通过一个比实际面板更大的离屏视口验收。原生桌面/移动应用使用目标平台的内容区域与缩放约定，不把 CSS px 机械换算成物理像素或原生窗口尺寸。

## 一屏通过的明确条件

桌面控制台在约定一屏档位及本次相关状态下，须同时满足：

1. 页面根滚动区域 `scrollWidth <= clientWidth + 1`，`scrollHeight <= clientHeight + 1`，允许 1 CSS px 的测量取整误差。内容尺寸取 `document.scrollingElement` 的 scrollWidth/scrollHeight，与 `document.documentElement` 的 clientWidth/clientHeight 比较，不任意改测 body 或某个较小容器。资料页等已允许纵滚的页面不适用纵向这一条。
2. 约定主操作和关键状态的实际边界完整位于可见内容区；没有被父容器裁切、固定顶栏/底栏、弹层或提示遮挡。根尺寸通过仍要检查实际画面和元素边界，不能仅凭数值宣布通过。
3. 内部滚动区的首末项、弹窗确认/取消和键盘焦点都可到达；完成本轮主任务无需寻找被藏起的控件。按控件的实际语义检查操作，不能只截图不走主线。
4. 截图必须包含实际可见视口；`fullPage` 长截图可补充，但不能作为“一屏”的通过依据。选中页、数据状态和视口信息必须对应，不用旧版或空态截图替代改后页面。

不能靠降低浏览器缩放、全局 `transform: scale()`、强行缩小字体/点击区域、根级隐藏溢出或裁掉内容通过。合理的裁图、模型画布或明确滚动容器可以使用 overflow；须证明没有隐藏任务所需信息。不能通过删除错误反馈或改成虚假成功来保持画面整洁。

## 发生溢出时的处理顺序

先检查信息与布局，再调整组件约束：

- 删除重复标题、研发说明和无必要的介绍卡；合并重复页面、共用同一可视区域。页面与模块数量围绕任务确定，不统一要求所有产品只做两页。
- 先分配高度预算。例：700 px 内容区，64 px 页头，上下各 12 px 外边距，主内容还剩 **612 px**；各行的最小高度、间距、边框和内边距总和必须容纳其中。这只是起算示例，不是统一皮肤尺寸。
- 用 Grid/Flex 分配剩余空间，核对 `min-height`、`min-width`、内容固有尺寸和盒模型；需要收缩的子项采用合适的 `min-height: 0`、`min-width: 0` 或 `minmax(0, 1fr)`。固定的大 `min-height` 不能反过来撑破视口。
- 按实际页头计算 `100dvh` 等可用高度；图片、视频、模型画布随区域缩放。低高度窗口需要检查高度断点，不能只写按宽度的媒体查询。
- 仍放不下时重排主次、调整共享区域或使用约定的内部滚动；低于支持下限则采用清楚的退化布局。不要用一层层嵌套切换或不断压小控件来掩盖问题。

## 验收范围与证据

首次/明显布局改动检查常规与最小桌面档，按目标范围补小窗/窄屏退化；后续局部修改复验受影响页面和最容易溢出的档位即可。正常、空数据、加载/错误、长名称和反馈弹出等状态按本次改动选取，不强制每个页面做全量组合矩阵。字号/缩放相关改动或项目已有可访问性要求时补测放大与重排；此时允许合理滚动，不套用 100% 缩放的一屏条件。

在已有验证说明保留：页面/版本、浏览器、实际视口与缩放、根区域内容尺寸、关键控件边界、已测状态、截图和主线操作结果。原始截图/测量按[输出约定](storage-and-outputs.md)放拥有项目的证据目录，不新增每轮总结文档。无法运行界面时明确未做视觉验收，不把构建或 CSS 断言当作一屏通过。

简短记录示例（待项目实际测量后填写）：

```text
页面/主任务：设备控制台；查看状态并执行主要操作
视口/缩放：1440×800、1280×700 CSS px；100%；浏览器及DPR按实记录
滚动合同：桌面根区域不滚；数据列表内部滚；小窗口允许纵滚
核心控件：本项目约定的主操作和关键状态
结果：实际根尺寸、控件可见边界、已测状态、截图与操作证据入口
```

## 使用与交接

本页可通过 `workspace-hub:workspace-hub#hub/ui-delivery` 定位；与网页复制的索引位置一起交给新会话，不复制完整规范到项目 AGENTS。可附一句：

> 按此界面约定处理当前 UI，先收敛信息层级，按项目视口与滚动合同完成画面和主线验收；研发说明留在已有文档。

规则更新不自动改写旧项目或已打开的会话；在获授权的界面任务中按需接入。原有产品行为与硬件、发布门禁不受界面精简替代。

技术口径参考：[MDN 视口](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/CSSOM_view/Viewport_concepts)、[内容高度](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollHeight)。
