# 可选的全局规则合并建议

本文件是人工整理的通用建议，不是原作者的全局 AGENTS，也不是自动安装脚本。使用者可按团队偏好选用；不需要为了采用 Hub 统一替换全部全局规则。

请先读取使用者现有的全局 AGENTS，核对已有的协作、授权和项目约束；只在当前授权范围内合并确实需要的短条目，去重并保留有效约束，不直接覆盖原文件或修改无关设置。当前客户端的能力、权限和更高优先级要求继续有效。

## 临时子 agent 的使用

- 主会话负责任务范围、架构、集成、审查和最终答复，对委派结果继续承担核对责任。
- 简单或紧密耦合的工作直接处理。当前授权允许，且工作可独立划定边界、有可验收结果并确有收益时，可使用临时子 agent；不把常规委派变成逐次重复审批。委派本身需要扩大访问、操作或任务范围时，再明确所需授权。
- 同一代码区域保持一个写入者；同一设备、串口、USB 外设或共享远程测试主机保持一个操作者。只读研究不能擅自启动硬件测试。
- 主会话持续跟进阻塞、交接和必要验证，按风险核对返回结果，并把可复用结论写回拥有该事实的项目文档。
- 子 agent 不扩大用户授权，也不替代目标项目的门禁。临时子 agent 不等于新的侧栏任务；只有用户明确要求时才创建长期会话，向其他长期会话发送消息也须有用户明确授权。
- 不在这些通用条目中写死模型、推理强度或并发数；按当前客户端提供的能力执行，不宣称这些规则能绕过客户端限制。

如需将 Hub 用作跨项目导航，可合并一条短入口；先将下面的占位替换为本机实际目录：

> 项目初始化、首次整理、交付约定、界面设计/实现/审查、状态更新或共享能力查询时，按需读取 `<实际Hub目录>/docs/hub/README.md`，只读当前任务相关规范。已知目标入口可直接进入；首次使用或上下文缺正文时仍需读取，只有正文未变且仍在上下文中才复用。目标项目自身约束和验收门继续有效。

详细规则留在 Hub 和拥有项目中，不把项目日志、长篇流程或机器参数复制到全局 AGENTS。
